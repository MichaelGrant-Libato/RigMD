2. Home and temperature monitoring
----------------------------------

- The Home dashboard adds a GPU card and adjusts its responsive grid. The GPU
  card shows each measured adapter's name, integrated or dedicated type, usage
  bar, and temperature where available. The CPU card also displays a fresh
  temperature with its source.
- DXCore enumerates hardware graphics adapters. RigMD matches Windows GPU
  engine readings to the adapter's LUID, adds process activity on the same
  engine, and takes the busiest engine's utilization. Independent engines and
  different adapters stay separate. The card distinguishes measured idle
  activity from an unavailable sample.
- GPU temperature comes from the installed Windows display driver through
  D3DKMT. A supported NVIDIA reading from nvidia-smi can fill a missing
  temperature when RigMD identifies the adapter. Temperature and utilization
  keep independent timestamps. Stale or missing readings clear from the UI.
- Optional CPU temperature uses LibreHardwareMonitorLib 0.9.6 with the signed
  PawnIO 2.2.0 driver and only the CPU hardware provider enabled. The collector
  checks driver access, selects an identified CPU temperature sensor, and
  supplies its source, sensor ID, and timestamp. It retries after transient
  sensor failures. Home and Device Info use that same measurement contract.
  A missing, inaccessible, or unsupported sensor shows "Not available".
- The setup wizard offers an unchecked CPU temperature option. The setup
  scripts pin the official driver installer by SHA-256 and verify its signer.
  Packaging includes matching upstream source archives, licenses, and setup
  and rollback notes. The app's telemetry loop performs read-only collection.
  PawnIO installation is a separate administrator-approved step. Driver
  removal is separate because other applications may share it. See
  installer/CPU-SENSORS.md for status, installation, and removal commands.

3. Storage software inventory
-----------------------------

- My Device Info > Storage has Overview, Installed apps, and Drivers views.
  Installed apps supports search, name or largest-first sorting, physical drive
  selection, and a Location unknown filter. Drive options show volume letters
  and the selected drive shows available space when measured.
- Apps come from machine and current-user desktop uninstall registrations in
  the 32-bit and 64-bit registry views, plus main AppX packages registered for
  the current user. Hidden system and child uninstall entries are filtered.
  RigMD maps a known local install path to its Windows volume and physical
  disk. App sizes are Windows or installer estimates, where supplied. The
  inventory covers the records exposed by those sources.
- Expand an entry for its publisher, version, source, install path, and
  estimated size, where available. App icons use local resource extraction
  or a package manifest logo. RigMD uses a fallback icon for missing or
  invalid resources. Drivers have distinct rows and icons.
- Drivers combines Plug and Play device records, driver services, and
  third-party Driver Store packages. Rows can show version, provider, INF,
  signer, service state, and other metadata. Drivers are informational, with
  an Open Device Manager handoff.
- Inventory supports manual refresh and discloses partial query results.
  Manage in Windows opens Installed apps in Settings. RigMD refreshes the
  app list on return and preserves the selected view and filters. Device
  Manager is launched using the Windows system path.

4. Direct uninstall for eligible apps
-------------------------------------

- An expanded eligible app shows Uninstall. Eligibility requires a verified
  machine-wide MSI registration, a single valid product code, and Microsoft's
  App Installer package. The review also checks WinGet command support.
  Protected items explain the restriction. Current-user apps, packaged apps,
  and unverifiable registrations use Manage in Windows as applicable.
- The confirmation shows the app and version, WinGet as the launcher, and
  machine-wide impact. On approval, RigMD consumes a one-time, three-minute
  approval ID, checks the registration again, and starts the native
  interactive uninstall for that exact MSI. Only one uninstall can run per
  local API process. The request sends an app ID or approval ID.
- RigMD reports Removed only after WinGet succeeds and the corresponding
  Windows Installer and uninstall registrations disappear. It distinguishes
  cancellation, restart, no match, failure, and unverified removal where the
  evidence supports that result. The list refreshes afterward. Product and
  exit codes can be inspected in the review or result where available.
- The authenticated local API adds these four routes:

    GET  /api/software-inventory/apps
    GET  /api/software-inventory/drivers
    POST /api/software-inventory/apps/uninstall-review
    POST /api/software-inventory/apps/uninstall

  Uninstall is a manual desktop action. The experiment updates the existing
  GPU and memory diagnostic payloads and leaves the ReAct tool registry count
  outside the scope of this feature. Approvals live in API process memory.

5. My Device Info telemetry and details
---------------------------------------

- The overview and detail dialogs share one Device Info SignalR feed. Live
  charts use a rolling 60-second time window. Stale and missing measurements
  create gaps. The UI uses Idle for measured inactivity, Collecting during
  warm-up, and Not available for missing evidence. The page distinguishes
  the inventory collection time from the live sampling time.
- Processor reports utilization, the Windows clock reading, the maximum
  clock reported by firmware, system process, thread and handle counts,
  temperature, sockets, physical and logical counts, firmware virtualization,
  installed L1/L2/L3 cache, and uptime. The Windows frequency counter
  can stay near the nominal clock. Treat it as that counter's reading.
- Memory shows live physical usage and availability, committed memory and
  its limit, cached memory, installed and hardware-reserved memory, configured
  speed, module form factor, and slot count. Cached memory uses standby and
  modified pages. Missing memory evidence stays distinct from measured zero.
- Storage matches per-disk Windows performance counters by physical disk ID.
  The detail shows activity, read/write rates, average response time when
  transfers occur, volumes, and volume space at collection. Windows storage
  metadata supplies the bus and media type where identified. Volume free
  space is calculated from matching volume totals and usage.
- Graphics selects a specific adapter on multi-GPU systems. It shows activity,
  separately sampled dedicated and shared memory, temperature, driver
  version, driver date, and PCI location where the adapter can be identified.
  DXCore reports capacities and WDDM supplies per-adapter memory usage.
  Legacy aggregate memory fields are available only when unambiguous.
- Windows and Computer Name cards open details for edition, build, system
  architecture, device identity, uptime, and active display count. The
  Computer Name view also includes motherboard information. Active display
  paths replace the old assumed single-display count.
- On laptops the Network card matches traffic and link speed to the selected
  interface. Battery and Power Plan open details. Live battery charge and
  charging status come from Windows power status. AC power alone is
  insufficient evidence of charging.
- The live hardware route returns expanded CPU, RAM, GPU, battery, network,
  display, storage, and inventory-timestamp fields. The telemetry hub adds
  timestamped frames, per-disk response readings, per-interface network
  speeds, and live battery status. Windows counters preserve unavailable
  samples and measured zero separately. Existing memory and GPU diagnostic
  payloads carry the corresponding verified fields or sensor provenance.
